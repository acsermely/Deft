## Arguments and behaviour

Use `call(method, args)` from `/_deft/v1/bridge.js`. Basics, errors and events: `skill.read name=js-bridge/basics`.

- intents (`intents.open`): `share` `{title?, text?, url?, files?: [{name, mime, base64}]}` opens the system share sheet. `navigator.share` uses it automatically.
- open with (manifest only, no call): `"handles": {"mimeTypes": ["image/*", "application/pdf"], "schemes": ["web+deft", "mailto"], "links": ["https://example.com"]}` (each at most 16; MIME types `type/subtype` or `type/*`, lowercase, never `*/*`; schemes `web+name` or `mailto`; links https origins). Other Android apps can then open files and links in your app through "Open with": the user picks your app in the launcher's list ("Always" remembers it; the app card in Settings has "Ask again"). Event `intents.viewReceived` `{type, url?, items: [{id, name, mime, size}]}` (queued until you subscribe): for a file, `type` is its MIME type and the copy is read once with `intents.readShare` `{id}` (24 h expiry, same as shares); for a link, `type` is the scheme and `url` the full `mailto:` or `web+deft:` URL. `mimeTypes` need `share.receive`, and only files Android sends as `text/*`, `image/*`, `audio/*`, `video/*`, `application/pdf`, `text/calendar`, `text/vcard` or `application/json` arrive. Only `web+deft` and `mailto` (send-to) links arrive: other `web+` schemes and `links` are accepted but do nothing, because Android cannot add link filters at run time; https links open in the browser.
- intents: `open` `{url}` — schemes `http` `https` `mailto` `geo` `tel` `sms` only
- intents out (`intents.start`): `start` `{action, type?, data?, extras?}` and `startForResult` (same args) → `{resultCode: "ok"|"cancelled", data?, items?: [{id, name, mime, size}]}`. Always the system chooser; you never learn which app ran. `action` is one of `SEND`, `SEND_MULTIPLE` (text only), `VIEW`, `EDIT`, `INSERT`, `PICK`, `GET_CONTENT`, `IMAGE_CAPTURE`, `VIDEO_CAPTURE`, `SET_ALARM`, `SET_TIMER`, `SHOW_ALARMS`, `DIAL`, `SENDTO`, `WEB_SEARCH`, `INSERT_OR_EDIT`. `data` schemes `http` `https` `mailto` `tel` `sms` `geo` only; `content:` and `file:` are refused. `type` is a MIME type. `extras` is at most 16 string keys named `android.intent.extra.*` or `android.provider.*`, values at most 4096 characters, and no file names. Content the other app returns is copied into the share inbox: read it with `intents.readShare` (needs `share.receive`). `IMAGE_CAPTURE` returns the photo as a JPEG item (a thumbnail; no output file is set). `startForResult` shows the app's result screen only; use it for a photo or a pick, not for background work. Without an answer after 10 minutes it rejects with `cancelled`.
- shares (`share.receive`): `intents.shareReceived` gives `{type, text, items: [{id, name, mime, size}]}`. `intents.readShare` `{id}` returns `{mime, base64}` once, then the item is gone. Unread items expire after 24 h. An app holds at most 50 unread items and 50 MB; past that, new files are refused (the user is told to open the app first), so read and drop items promptly. Shared files are not visible to `files.*`.
