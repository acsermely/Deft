## Arguments and behaviour

Use `call(method, args)` from `/_deft/v1/bridge.js`. Basics, errors and events: `skill.read name=js-bridge/basics`.

- clipboard (`clipboard.read`): `readText` → `{text}`, only within 5 s of a tap. `navigator.clipboard.readText` uses it automatically.
- clipboard watch (`clipboard.watch`, SPECIAL: the user grants it from the app's card on the dashboard; foreground only): `watchStart` starts reporting copies, `watchStop` stops. Each new copy arrives as `clipboard.changed` `{text}`: the plain text, at most 64 KiB, or `{text: null}` when the copy is not text (images, files) or is marked sensitive (a password or one-time code copied by a password manager). The listener ends when the app leaves the screen. Android only tells an app about clipboard changes while the app is in front, so copies made in other apps are not seen, except in keyboard mode: when the app also holds `ime` and Deft's keyboard is the phone's chosen keyboard, its keyboard page may call `watchStart` too, and then gets every copy made in any app while that page is open and listening (never queued; it ends with `watchStop`, when the keyboard page closes or another keyboard is chosen). Clipboard text is sent to the app only; the launcher never logs it.
- display (`display`): `keepScreenOn` `{on}`, `setOrientation` `{orientation}` (`any`, `natural`, `portrait`, `landscape`, `portrait-primary`, …), `print` `{title?}`, `secure` `{on}` (no screenshots, blank in Recents and screen sharing; cleared when the app closes), `hideOverlays` `{on}` (Android 12+; other windows cannot draw over the app). `navigator.wakeLock.request('screen')`, `screen.orientation.lock()` and `window.print()` use them automatically.
- torch (`torch`): `set` `{on, level?}` turns the back camera flashlight on or off (`level` `1` to `maxLevel`, default the strongest; → `{on, level, maxLevel}`); `state` → `{available, on, maxLevel}` (`on` follows the flashlight even when the user or another app switched it). Foreground only: the light goes off when the app leaves the screen. Devices without a flash fail `set` with `unsupported`.
- pip (`pip`): `enter` `{aspect?}` shows the app in a small picture-in-picture window now; `setAuto` `{on, aspect?}` does the same when the user leaves the app (Home). `aspect` is `w:h` such as `16:9` (the default). Foreground only. Window changes arrive as `pip.changed` `{inPip}`. Devices without picture-in-picture fail with `unsupported`.
- sensors (`sensors`): `list` → `[{type, name, vendor, maxRate, maxRange, resolution}]` (`maxRange` and `resolution` in the sensor's unit; proximity with maxRange 5 and resolution 5 is near/far only) for `stepCounter`, `stepDetector`, `light`, `pressure`, `proximity`, `magnetometer`, `humidity`, `ambientTemperature`, `accelerometer`, `gravity`, `linearAcceleration`, `rotationVector` (only the ones the device has); `subscribe` `{type, rateHz?}` (1 to 50 Hz, default 5; at most 4 at a time) → `{id}`; readings arrive as `sensors.reading` `{id, type, values, timestamp}`; `unsubscribe` `{id}`. Types: proximity = near/far only (0 or maxRange), never a distance; accelerometer = m/s² including gravity (about 9.8 at rest), present on every phone; gravity, linearAcceleration and rotationVector need a gyroscope and are missing on many budget phones, so check `list` and fall back to accelerometer minus the reading taken while still (holds only if the phone does not tilt); linearAcceleration = m/s² without gravity, x/y/z in the phone's frame (distance moved = integrate twice, reset velocity to 0 whenever the phone is still; only rough, often 10-30% off over a metre, drift grows with time); gravity = m/s², the tilt direction; rotationVector = orientation quaternion, use it for heading and tilt instead of raw magnetometer; magnetometer = µT, disturbed by metal and magnets; light = lux; pressure = hPa, about 8 m of altitude per hPa, relative changes only; humidity and ambientTemperature are missing on most phones; stepCounter = cumulative steps since boot, stepDetector = one event per step. Foreground only: an app's sensors stop when it leaves the screen. `stepsToday` → `{today, days: [{date, steps}]}` (30 local days, oldest first, last is today; no `{type}`): daily totals the launcher keeps itself, also while the app is closed and in background runs. Counting starts at the first `stepsToday` call, so earlier days are 0 because they are unknown, not because nothing was walked. Tell the user this (e.g. "Step history starts today; earlier days show 0"), and do not present a short history as a full one. The first call must come from the app on screen: a widget or background run gets `os_permission_missing` until the user allows physical activity access. Needs physical activity access, else `os_permission_missing`. `stepCounter` and `stepDetector` need physical activity access (Android 10 and newer), else `os_permission_missing`.
- system stats (`system.stats`): `stats` → `{memory: {total, available, low}, thermal: {status, headroom}, battery: {level, charging, tempC, currentMa}, storage: {total, free}, cpuFreq?}`. Bytes for memory and storage; `status` is `none`, `light`, `moderate`, `severe`, `critical`, `emergency` or `shutdown`; `headroom` about 0 to 1 (1 = throttling, null if unknown); `level` percent; `currentMa` sign depends on the device, null if unsupported; `cpuFreq` MHz per core, left out when unreadable. What it does not have: no phone-wide CPU load percentage and no SoC or skin temperature. The only temperature is `battery.tempC`, and `thermal.status` is a band, not degrees. When the user asks for CPU load or skin temperature, say the phone does not expose it to apps, then show what is there (`cpuFreq`, `battery.tempC`, `thermal.status`). Never estimate or invent a number. For a live gauge, see `skill.read name=deft-design/references/recipes/widgets.md`. At most one call a second per app (`rate_limited`). Works in background runs.
- audio (`audio.control`): `getVolumes` → `{music, ring, alarm, notification, voiceCall}` each `{value, max}`; `setVolume` `{stream, value}` (`stream` one of those names; `value` a whole number, clamped to 0..max; shows the system volume panel; a change that would turn on silent needs Do Not Disturb access, else `os_permission_missing`) → `{value, max}`; `getRingerMode` → `{mode}`; `setRingerMode` `{mode}` (`normal`, `vibrate`, `silent`; `silent` needs Do Not Disturb access, else `os_permission_missing`); `devices` → `[{id, type, name}]` for output devices (`type` `speaker`, `earpiece`, `wired`, `bluetooth`, `usb`, `other`); `route` `{target}` (`speaker`, `earpiece`, `bluetooth`, `default`) picks where call-style audio plays (Bluetooth includes LE Audio headsets) → `{target}`; the phone goes back to its default output when the app leaves the screen or loses `audio.control`. Foreground only.
- dnd (`dnd`): `state` → `{filter, accessGranted}` (`filter` `all`, `priority`, `alarms` or `none`); `set` `{filter}` (same names) → `{filter}`; `requestAccess` opens the system Do Not Disturb access screen once (→ `{accessGranted}`: the call waits until the user is back in the app and reads the state then; it returns at once if the screen did not cover the app). Without access `set` gives `os_permission_missing`. Foreground only.
- keystore (`keystore`): keys made here stay on this phone; the app gets public keys, signatures and ciphertext, never key material. `generate` `{alias, alg, requireBiometric?, validitySeconds?}` (`alias` 1 to 64 letters, digits, `_` or `-`; `alg` `EC_P256` or `AES_256`; `requireBiometric` `"true"` locks the key with fingerprint or face, and `validitySeconds` 0 to 3600 (default 0, every use asks) keeps it unlocked that long; needs `requireBiometric`) → `{alias, publicKeySpki?}` (base64 SPKI, EC keys only); `sign` `{alias, base64}` (EC, SHA-256 ECDSA) → `{signature}` (base64 DER); `encrypt` `{alias, base64}` (AES-GCM) → `{iv, ciphertext}` (base64); `decrypt` `{alias, iv, ciphertext}` → `{base64}`; `list` → `[alias]`; `delete` `{alias}` (confirmed every time; cannot be undone). Keys belong to the app and no other app sees them. Foreground only. A locked key shows a fingerprint or face prompt; a failed or cancelled check gives `cancelled`.
- speech (`speech.tts`, `speech.recognize`): `speak` `{text, lang?, rate?, pitch?, id?}` (`rate` and `pitch` 0.25 to 4, default 1; text up to 4000 characters) → `{id}`, then `speech.done` `{id}` or `speech.error` `{id, code}` (`code` `interrupted` when another app stopped the phone's voice); the voice is shared by every app: a new `speak` replaces the app's own speech but waits behind another app's; `stop` stops the voice only while the app's own speech is playing; `voices` → `[{name, lang, offline}]`. `recognize` `{lang?, offline?}` (`offline` `"true"` prefers on-device recognition) listens for one utterance and returns `{text, alternatives}` (`alternatives`: up to 5 other guesses, best first, without `text`); partial text arrives as `speech.partial` `{text}`. `cancel` ends listening. No result within 60 s gives `cancelled`. Listening needs the microphone grant, the app on screen and a tap in it within 5 s; it stops when the app leaves the screen.
- Standard web APIs behind a grant, no bridge call: `haptics` (`navigator.vibrate`), `media.drm` (Encrypted Media Extensions / Widevine), `midi` (Web MIDI with sysex), `payments.request` (`PaymentRequest`, paid through installed payment apps), `network.open` (`fetch`, XHR, `WebSocket`, `EventSource`, images and media from any `https:` / `wss:` origin; reading a response still needs the server's CORS headers), `network.user` (servers the user adds on the app's card in Settings count like allowed `network` origins), `wasm` (`WebAssembly` compiles and runs the `.wasm` files in the app, or hash-pinned `.wasm` dependencies; declare it, then load the file with `fetch` and `WebAssembly.instantiate`), `storage.large` (no call: the app package may be larger than the usual limit, up to the free space on the phone and 2 GiB, with binary files up to 200 MiB; the user grants it, and only a granted app gets the larger cap; asset packs are not covered yet), `net.sockets` (no call of its own: the `net.*` methods may connect to addresses outside the LAN, so the app declares it and the user grants it along with `network.open`; a LAN-only app needs neither), `web.embed` (scripts, iframes, `fetch` and images from the origins listed in manifest `embeds`, e.g. `["https://js.stripe.com", "https://*.js.stripe.com"]`: at most 16, `https://` only, `*.` only as the leftmost label, no IPs or localhost; the user approves each origin and can refuse some; that code runs with all of the app's grants; load SDKs the way their docs say, e.g. a `<script>` element created from `main.js`, since Trusted Types lets script URLs through only for approved origins). Images and media load from the same origins as `fetch`. `<input type="file">` (with `capture`) and the Fullscreen API need no grant.
- device admin (`device.admin`, SPECIAL, one app at a time: the user grants it from the app's card on the dashboard, and the same sheet asks Android to activate Deft as a device admin app; until that is on, `lockNow` returns `os_permission_missing` with message `Device admin app`): `admin.lockNow` → `{locked: true}` locks the screen at once, like the power button. It works from the app on screen and from background runs (lock on a trigger); at most one lock every 30 seconds, sooner gives `in_use`. `admin.status` → `{active}`, whether Android has the launcher's device admin on. The device admin can only lock the screen: there is no wipe, no password or screen-lock rules, no camera switch, and no method will add them (wipe is refused by design). While it is on, Android will not uninstall Deft. Revoking the grant or removing the app turns the device admin off; the user can also turn it off in Android Settings under Security, Device admin apps.
- device (`device.id`, works in the background too): `id` → a 32-character hex string, the same every time this app opens on this phone and different for every other web origin. Other apps and origins cannot see it. Clearing app data on the phone or reinstalling the launcher gives a new id.
