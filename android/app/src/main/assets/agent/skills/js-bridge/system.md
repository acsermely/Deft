## Arguments and behaviour

Use `call(method, args)` from `/_deft/v1/bridge.js`. Basics, errors and events: `skill.read name=js-bridge/basics`.

- apps (`apps.list`, SPECIAL: the user grants it from the app's card on the dashboard, after the screen lock; foreground only): `list` → `[{package, label, system}]`, launchable apps only, one row per package, sorted by name, without the launcher itself; `icon` `{package}` → base64 PNG (96 px) of that app's icon.
- apps (`apps.launch`, foreground only): `launch` `{package}` opens that app. The launcher itself is refused (`unsupported`).
- usage (`usage.read`, SPECIAL, one app at a time; foreground only): `stats` `{sinceMs, untilMs}` (epoch milliseconds, `sinceMs` before `untilMs`, at most 366 days) → `[{package, foregroundMs, lastUsed}]`, most used first, apps with no foreground time left out. The user turns on Usage access in system settings; until then the call returns `os_permission_missing` with message `Usage access`.
- sign-in (`auth.session`, needs its grant; foreground only): `auth.prepare` → `{nonce, redirectUri}`. Put `redirectUri` in the sign-in URL as `redirect_uri`, and always use PKCE and a `state` value: any Android app can register the same custom scheme and may receive the redirect instead, so the code alone must be useless without your PKCE verifier. Then call `auth.start {url, nonce}` from a tap handler (url must be `https://`); it opens the page in a Custom Tab and resolves with `{url}`: the full redirect URL, which carries the code, and brings the app back to the front. Without a tap in the app within the last 5 s it rejects with `not_granted` ("needs a tap"). It rejects with `cancelled` when the user closes the tab or after 10 minutes. A nonce works once, for the app that made it, and expires after 10 minutes.
- push (`push`, medium; no Google services, needs a UnifiedPush distributor app such as ntfy on the phone): `register` → `{endpoint}`, the URL your server POSTs messages to (body at most 4096 bytes; bigger ones are dropped). Fails with `unsupported` "Install a UnifiedPush distributor such as ntfy" when none is installed, or when the distributor does not answer within 15 s. Calling it again returns the same endpoint. `unregister` drops the endpoint; `status` → `{registered, endpoint?, distributor?}` (`distributor` is the push app's package name). Event `push.message` `{base64}` (the raw message bytes) reaches the open page at once. When the app is closed the event waits for the next open, and also: with the `background` grant and the manifest trigger `push`, the background module runs with `payload` `{base64}`; otherwise, when the message is JSON with string `title` and `body`, it shows as a notification on the app's default channel (tap opens the app). Event `push.endpointChanged` `{endpoint}` when the distributor gives a new endpoint (send it to your server); `push.unregistered` `{}` when the distributor dropped the app (register again). Revoking `push` or removing the app unregisters it. Messages and endpoints are never written to the audit log.
- accounts (`accounts.own`, medium; works in background runs too): the app's own accounts in the phone's account list (system Settings → Accounts, under "Deft apps"), shown as "<name> · <App name>". No passwords or tokens are stored: keep sign-in data in the app's own storage. `add` `{name}` (trimmed, 1 to 64 characters, no control characters; at most 8 per app; adding an existing name is fine) → `{name, shownAs}`; `in_use` when another app with the same app name already has that name. `list` → `[{name, periodicSeconds}]`, this app's accounts only (`periodicSeconds` 0 when none is set). `remove` `{name}`. `requestSync` `{name}` asks Android to sync that account soon; `setPeriodicSync` `{name, seconds}` (0 turns it off, else 900 to 2592000) asks for a sync about that often (Android may delay it, and skips it while the user has turned off auto-sync). A sync wakes the app's background module with trigger `sync` `{account: name}`: declare `"sync"` in `background.triggers` and hold `background`, otherwise the sync does nothing. Unknown names fail with `invalid_args` "no such account". The user can remove an account in Settings; uninstalling the app or revoking `accounts.own` removes all of them. "Add account" in Settings only says to add accounts from the app.
- accounts (`accounts.read`, SPECIAL: the user grants it from the app's card on the dashboard; foreground only): `listAll` → `[{name, type}]`, e.g. `{name: "me@example.com", type: "com.google"}`. On Android 8 and newer this is only the accounts Android lets the launcher see: those whose app made them visible to other apps, and contact-syncing accounts while the launcher has the contacts permission; many accounts are left out, and the list may be empty. Accounts added by Deft apps (`accounts.own`) are never listed.
